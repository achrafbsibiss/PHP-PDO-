# 📚 TP CRUD PHP/MySQL - Documentation Complète

## 🎯 Vue d'ensemble du projet

Ce projet est un TP progressif qui vous guide à travers 3 étapes d'évolution d'une application CRUD (Create, Read, Update, Delete) en PHP/MySQL, depuis une approche classique jusqu'à une architecture moderne avec AJAX.

### Processus de Création d'Utilisateur

```mermaid
sequenceDiagram
    participant U as Utilisateur
    participant B as Navigateur
    participant C as create.php
    participant DB as Base de données
    
    U->>B: Clic "Nouvel Utilisateur"
    B->>C: GET create.php
    C->>B: Affiche formulaire
    
    U->>B: Remplit formulaire + Submit
    B->>C: POST données
    
    C->>C: Validation email
    C->>C: Validation password
    C->>C: Vérification confirmation
    
    alt Validation OK
        C->>C: Hachage password
        C->>DB: INSERT INTO users
        DB-->>C: Succès
        C->>B: Redirect vers index.php
        B->>U: Affiche liste + message succès
    else Validation Échec
        C->>B: Affiche formulaire + erreurs
        B->>U: Erreurs affichées
    end
```

## 🔄 Étape 2 : CRUD dans un Seul Fichier

### Architecture de Routage

```mermaid
flowchart TB
    Start([Requête HTTP]) --> Index[index.php]

    List -->|POST action=delete| DeleteProcess[Traiter suppression]
    
    CreateProcess --> Redirect[Redirection vers<br/>?action=list]
    UpdateProcess --> Redirect
    DeleteProcess --> Redirect
    
    Redirect --> List
    
    style Index fill:#ffeb3b

```

### Logique de Traitement des Actions

```mermaid
flowchart TD
    Start([Requête reçue]) --> Method{Méthode<br/>HTTP?}
    
    Method -->|GET| GetAction{action=?}
    Method -->|POST| PostAction{POST<br/>action=?}
    
    GetAction -->|list| QueryDB[SELECT * FROM users]
    GetAction -->|view| QueryOne[SELECT * WHERE id=X]
    GetAction -->|edit| QueryOne
    GetAction -->|create| ShowForm[Afficher formulaire vide]
    
    PostAction -->|create| ValidateCreate{Validation<br/>données}
    PostAction -->|update| ValidateUpdate{Validation<br/>données}
    PostAction -->|delete| DeleteDB[DELETE FROM users]
    
    ValidateCreate -->|OK| InsertDB[INSERT INTO users]
    ValidateCreate -->|Erreur| ShowFormError[Afficher formulaire<br/>+ erreurs]
    
    ValidateUpdate -->|OK| UpdateDB[UPDATE users]
    ValidateUpdate -->|Erreur| ShowFormError
    
    InsertDB --> Success[Redirect + message succès]
    UpdateDB --> Success
    DeleteDB --> Success
    
    QueryDB --> Display[Afficher tableau]
    QueryOne --> DisplayDetail[Afficher détails]
    ShowForm --> DisplayForm[Afficher formulaire]
    
    style Method fill:#ffeb3b
    style GetAction fill:#4caf50
    style PostAction fill:#ff9800
    style Success fill:#8bc34a
```

## 🔐 Flux de Sécurité - Hachage de Mot de Passe

```mermaid
flowchart TD
    Start([Utilisateur saisit mot de passe]) --> Client[Formulaire HTML]
    
    Client -->|POST| Server[Serveur PHP]
    Server --> Validate{Validation<br/>longueur >= 6}
    
    Validate -->|Non| Error[Retourne erreur]
    Validate -->|Oui| Hash[password_hash<br/>PASSWORD_DEFAULT]
    
    Hash --> Store[Stockage en BD<br/>Hash bcrypt]
    
    subgraph "Exemple de transformation"
        Plain["'motdepasse123'"] --> Hashed["'$2y$10$...'<br/>(60 caractères)"]
    end
    
    Store --> Success[Succès]
    
    style Start fill:#e3f2fd
    style Validate fill:#fff9c4
    style Hash fill:#c8e6c9
    style Store fill:#4caf50
    style Error fill:#ffcdd2
```

## 🛡️ Flux de Validation des Données

```mermaid
flowchart TD
    Start([Données reçues]) --> Clean[cleanInput<br/>trim, stripslashes, htmlspecialchars]
    
    Clean --> ValidateEmail{validateEmail}
    ValidateEmail -->|Invalide| Error1[Erreur: Email invalide]
    ValidateEmail -->|Valide| CheckPassword{Password<br/>>= 6 caractères?}

    CheckPassword -->|Oui| CheckConfirm{Password ==<br/>Confirm?}
    
    CheckConfirm -->|Non| Error3[Erreur: Passwords différents]

    CheckRole -->|Oui| Prepare[Requête préparée PDO]
    
    Prepare --> Execute{Exécution<br/>requête}
    Execute -->|Duplicate email| Error5[Erreur: Email existe déjà]
    Execute -->|Succès| Success[✓ Données enregistrées]
    
    Error1 --> DisplayErrors[Afficher erreurs]
    Error2 --> DisplayErrors
    Error3 --> DisplayErrors
    Error4 --> DisplayErrors
    Error5 --> DisplayErrors
```

## 📝 Conclusion

Ce TP vous permet de comprendre l'évolution des architectures web PHP, depuis une approche procédurale simple jusqu'à une architecture moderne séparant le front-end (JavaScript) du back-end (API REST PHP).

**Points clés à retenir:**
- 🔒 **Sécurité**: Toujours utiliser des requêtes préparées et hasher les mots de passe
- 🎯 **Validation**: Valider côté serveur ET client
- 📦 **Modularité**: Séparer les responsabilités (MVC)
- ⚡ **Performance**: AJAX améliore l'expérience utilisateur
- 🛠️ **Évolutivité**: L'API REST permet de créer plusieurs interfaces (web, mobile, etc.)
